# WebForApplications

REST API веб-сервис для управления и отслеживания жизненного цикла внутренних заявок.

## Описание проекта

WebForApplications — это серверное приложение, предназначенное для автоматизации процессов приема, распределения, обработки и контроля исполнения внутренних заявок. Системы подобного класса позволяют организовать прозрачный учет обращений, автоматизировать смену статусов и формировать аналитическую отчетность по работе исполнителей.

### Основные возможности

* **Управление жизненным циклом заявок:** создание, редактирование, обновление статусов (Новая -> В работе -> Завершена / Отклонена).
* **Назначение исполнителей:** привязка заявок к конкретным сотрудникам и контроль за ходом выполнения.
* **Фильтрация и поиск:** гибкая выборка заявок по статусам, исполнителям, диапазонам дат и ключевым словам.
* **Аналитика и отчетность:** отслеживание просроченных обращений, подсчет метрик продуктивности и сводная статистика.
* **Интерактивная документация:** встроенный Swagger UI для тестирования и интеграции API.

## Технологический стек

* **Платформа:** .NET 8.0 / ASP.NET Core
* **База данных:** PostgreSQL 15+
* **ORM:** Entity Framework Core
* **Генерация тестовых данных:** Bogus
* **Маппинг объектов:** Mapster
* **Контейнеризация:** Docker, Docker Compose
* **Тестирование:** xUnit, Moq, FluentAssertions
* **Документация API:** Swagger / OpenAPI
* **Документация проекта**: Gemini

## Архитектура и структура проекта

Построение REST API на базе ASP.NET Core:

* Разделение на слои (Controllers, Services, Repositories, DTOs).
* Автоматическая миграция схемы базы данных с использованием EF Core Migrations.
* Валидация входных данных и обработка ошибок на уровне Middleware.
* Изолированное модульное и интеграционное тестирование бизнес-логики.

## Инструкция по запуску

### Вариант 1. Запуск через Docker Compose (Рекомендуемый)

Данный способ автоматически разворачивает контейнеры с базой данных PostgreSQL и REST API сервисом.

1. **Клонируйте репозиторий:**
   ```bash
   git clone [https://github.com/mrklimacc-ctrl/WebForApplications.git](https://github.com/mrklimacc-ctrl/WebForApplications.git)
   cd WebForApplications

   2. **Запустите сборку и контейнеры:**
   ```bash
   docker-compose up -d --build
   ```

3. **Проверьте работоспособность:**
   После успешного старта API и Swagger UI будут доступны по адресу:
   ```text
   http://localhost:8080/swagger
   ```

---

### Вариант 2. Локальный запуск (.NET CLI + Docker/Local Postgres)

1. **Клонируйте репозиторий:**
   ```bash
   git clone https://github.com/mrklimacc-ctrl/WebForApplications.git
   cd WebForApplications
   ```

2. **Запустите экземпляр PostgreSQL:**
   Вы можете использовать Docker для быстрого подъема СУБД:
   ```bash
   docker run --name postgres-apps -e POSTGRES_DB=applications_db -e POSTGRES_USER=postgres -e POSTGRES_PASSWORD=postgres -p 5432:5432 -d postgres:15-alpine
   ```

3. **Настройте строку подключения:**
   Убедитесь, что в файле `appsettings.Development.json` указаны корректные параметры подключения к PostgreSQL:
   ```json
   {
     "ConnectionStrings": {
       "DefaultConnection": "Host=localhost;Port=5432;Database=applications_db;Username=postgres;Password=postgres"
     }
   }
   ```

4. **Примените миграции базы данных:**
   Выполните команду обновления структуры БД до актуального состояния:
   ```bash
   dotnet ef database update
   ```

5. **Запустите проект:**
   ```bash
   dotnet run --project WebForApplications
   ```

6. **Перейдите в браузер:**
   Откройте Swagger UI для ознакомления с эндпоинтами:
   ```text
   https://localhost:7001/swagger
   ```
   (или `http://localhost:5001/swagger` в зависимости от настроек Kestrel).

---

### Инициализация и тестовые данные

При первом запуске приложения и выполнении миграций база данных автоматически заполняется демонстрационными (фейковыми) данными с помощью библиотеки **Bogus**. 

Это позволяет сразу после старта тестировать эндпоинты в Swagger UI (получать список заявок, фильтровать их и анализировать продуктивность исполнителей) без необходимости вручную создавать первые записи.
